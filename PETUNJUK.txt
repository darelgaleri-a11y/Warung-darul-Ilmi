WARUNG DARUL ILMI — AUDIT MIGRATION

Saya memeriksa ulang branch `app` sebelum menyiapkan paket ini.

Temuan:
1. Database awal v1 berada di root repository, bukan di `supabase/migrations`.
2. File v2, v3, v4, v5, dan perbaikan trigger juga berada di root.
3. Folder `supabase/migrations` hanya berisi migration 001, 002, dan 003.
4. Karena itu, instalasi Supabase baru dengan `supabase db push` tidak akan membangun schema aplikasi dari nol.
5. Database produksi yang sudah berjalan tidak boleh menerima SQL v1-v5 ulang begitu saja.

Isi ZIP:
- `supabase/migrations/README-MIGRATION-ORDER.txt`: temuan dan urutan migrasi.
- `periksa-migration-order.ps1`: menampilkan panduan; tidak mengubah database.
- `PETUNJUK.txt`: panduan penggunaan.

PENTING:
Paket ini adalah bahan audit/penataan, bukan migration SQL siap deploy. Saya sengaja tidak membuat baseline SQL palsu atau memindahkan SQL lama otomatis, karena kita belum memiliki schema dump aktual dari Supabase produksi. Cara yang aman adalah mengambil schema-only dump dari database saat ini, meninjaunya, lalu membangun baseline untuk proyek baru. Untuk database produksi, migration lama perlu di-baseline/stamp sesuai history dan kondisi schema; jangan jalankan ulang v1-v5.

Sebelum membuat ZIP migration eksekusi yang final, jalankan:
`npx supabase migration list --remote`
dan kirim hasilnya. Database project produksi perlu dibandingkan dengan urutan file lokal agar baseline tidak merusak data atau policy.
